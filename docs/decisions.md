## 2026-08-16 — Первая итерация бэкенда

### Контекст
Нужен минимальный, но расширяемый бэкенд: асинхронное FastAPI-приложение,
асинхронная работа с БД, витрина портфолио с пагинацией и форма-заявка
на проект. Фронтенд отложен на следующую итерацию.

### Решения

**PostgreSQL + asyncpg вместо SQLite.**
Продакшн-путь берём сразу: нормальные типы (`ENUM`, `TIMESTAMPTZ`),
конкурентная запись, полноценные миграции. Локально поднимается через
`docker-compose.yml`. Цена — нужен запущенный контейнер для разработки.

**SQLAlchemy 2.0 async + Alembic.**
`create_async_engine` + `async_sessionmaker`, типизированный стиль
`Mapped[...]`/`mapped_column`. Alembic настроен на асинхронный движок,
URL подставляется из `app.config`, а не из `alembic.ini`.

**Пагинация offset/limit, серверная.**
Витрина портфолио — это сетка с номерами страниц, где нужен переход на
произвольную страницу и общее число страниц. Курсорная пагинация это не
даёт. Срез делает БД (`OFFSET/LIMIT` + отдельный `COUNT`), наружу уходит
только текущая страница. Сортировка `created_at DESC, id DESC` —
вторичный ключ нужен для детерминированного порядка при одинаковых датах,
иначе одна и та же работа может попасть на две страницы. Под неё заведён
индекс `ix_portfolio_items_created_at_id`.

Ограничение подхода: на больших смещениях `OFFSET` деградирует, а вставка
новых работ во время листания сдвигает элементы. Для портфолио в сотни
записей это не проблема. Схема `Page[T]` универсальна, поэтому курсорный
вариант можно добавить рядом, не ломая существующий контракт.

**Модель портфолио — минимальная.**
Только `title`, `slug`, `description`, `cover_image`, `created_at`.
Категории, галерея изображений, `is_published` и `sort_order` сознательно
отложены до появления реального контента.

**Форма-заявка: имя и телефон обязательны, email опционален.**
Телефон нормализуется на уровне Pydantic-схемы к виду `+<цифры>`,
российский формат `8XXXXXXXXXX` приводится к `+7XXXXXXXXXX`. Благодаря
этому проверка дубликатов работает по каноническому номеру. Взяли регулярку,
а не библиотеку `phonenumbers`: одна зависимость меньше, а строгая проверка
операторских кодов нам пока не нужна.

Антидубль: повторная заявка с того же номера в течение 5 минут отклоняется
с `409`. Это защита от двойного клика по кнопке, а не rate limiting —
полноценное ограничение по IP появится вместе с реверс-прокси.

**Слоистая архитектура с зависимостями внутрь.**
`endpoints → services → repositories → models`. Сервисы не импортируют
FastAPI, а зависят от `typing.Protocol`, описывающего нужный им репозиторий.
Протокол объявлен в самом сервисном модуле, чтобы домен не смотрел наружу.
Так сервис тестируется на заглушке без БД.

**Транзакции — на уровне зависимости `get_db`.**
Один HTTP-запрос — одна транзакция: коммит при успехе, откат при любом
исключении. Репозитории делают только `flush`, чтобы получить `id`.
Альтернатива — коммит внутри сервиса — размывала бы границы транзакции
между несколькими сервисами в одном запросе.

**Доменные исключения вместо `HTTPException` в сервисах.**
`NotFoundError`, `ConflictError`, `ValidationError` переводятся в 404/409/422
обработчиками в `app/main.py`. Сервисный слой остаётся независимым от HTTP.

**Тесты по умолчанию на SQLite в памяти.**
`pytest` запускается без внешней инфраструктуры; для проверки на реальном
движке достаточно задать `TEST_DATABASE_URL` с asyncpg. Риск расхождения
диалектов есть, поэтому корректность SQL миграции проверяется отдельно
через `alembic upgrade head --sql`.

### Результат
18 тестов проходят, `ruff check` чистый, миграция `0001_init` генерирует
корректный PostgreSQL-SQL. Доступны эндпоинты: `GET /api/v1/health`,
`GET /api/v1/health/db`, `GET /api/v1/portfolio`, `GET /api/v1/portfolio/{slug}`,
`POST /api/v1/portfolio`, `POST /api/v1/leads`. Контракт описан в `docs/api.md`.

### Открытые вопросы
- `POST /api/v1/portfolio` пока без авторизации — закрыть вместе с админкой.
- Загрузка изображений не реализована: `cover_image` хранит строку-путь.
- Уведомление о новой заявке (почта или мессенджер) не сделано.

## 2026-08-30 — Админ-API, JWT, прод-Docker

### Контекст
Публичная витрина и заявки уже работали, но запись в портфолио была открытой,
`jwt==1.4.0` не совпадал с `jwt.encode`/`decode` (нужен PyJWT), compose был
dev-сценарием с паролями в файле и healthcheck на несуществующий `/health`.

### Решения
- Запись портфолио только под Bearer JWT: `POST/PATCH/DELETE /api/v1/admin/portfolio…`.
  Публичные `GET /portfolio` и `GET /portfolio/{slug}` не ломаем: админский
  префикс `/admin`, чтобы `{slug}` не перехватывал `admin`.
- Неверный логин и пароль — один `UnauthorizedError` → HTTP 401.
- В `production` отключены `/docs` и `/openapi.json`. Медиа отдаются как
  `StaticFiles`; в работах хранятся URL, без загрузки бинарников.
- JWT: зависимость **PyJWT**, не пакет `jwt`.
- Прод: корневой `docker-compose.yml` (`db` + `backend` + `frontend` nginx :80),
  секреты из `.env`. Локалка: `docker-compose.dev.yml` (Vite + прокси на backend).
  Healthcheck: `GET /api/v1/health` и `/api/v1/health/db`.

### Результат
Админка на сайте (`/admin/login`, таблица и форма работ), закрытый write API,
документация и примеры env обновлены.
