# API Плюс Дизайн

Сайт-визитка дизайнера интерьера: витрина проектов и заявки на работу.
Базовый префикс: `/api/v1`.

В `local` / `test` интерактивная документация — `/docs`, схема — `/openapi.json`.
В `production` оба адреса отключены.

Все ответы в JSON. Ошибки приходят в едином формате:

```json
{ "detail": "Работа со slug 'x' не найдена" }
```

Соответствие доменных исключений и HTTP-кодов задано в `app/main.py`:

| Исключение | Код |
| --- | --- |
| `UnauthorizedError` | 401 |
| `NotFoundError` | 404 |
| `ConflictError` | 409 |
| `ValidationError` | 422 |
| ошибка валидации Pydantic | 422 |

## Health

### `GET /api/v1/health`

Проверка живости процесса. БД не трогает.

```json
{ "status": "ok" }
```

### `GET /api/v1/health/db`

Выполняет `SELECT 1` в БД. Годится для readiness-проб.

```json
{ "status": "ok", "database": "ok" }
```

## Справочники

Публичные списки категорий и тегов. Фильтрация витрины по ним на фронте
в этой итерации не делается.

### `GET /api/v1/categories`

```json
[{ "id": 1, "name": "Квартира", "slug": "kvartira" }]
```

### `GET /api/v1/tags`

Тот же формат `NamedSlug`.

## Портфолио (публичная витрина)

Запись (`POST`/`PATCH`/`DELETE`) на `/api/v1/portfolio` **закрыта**.
Создание и правка — только в админ-API.

### `GET /api/v1/portfolio`

Список **опубликованных** работ. Пагинация серверная: срез делает БД
через `OFFSET/LIMIT`, наружу уходит только текущая страница.

Query-параметры:

| Параметр | Тип | По умолчанию | Ограничения | Описание |
| --- | --- | --- | --- | --- |
| `page` | int | `1` | `>= 1` | Номер страницы, нумерация с 1 |
| `size` | int | `12` | `1..100` | Количество элементов на странице |
| `category` | string | — | slug | Фильтр по категории (для будущего UI) |
| `tag` | string | — | slug | Фильтр по тегу (для будущего UI) |

Сортировка: `sort_order ASC, created_at DESC, id DESC`.

Ответ `200` — `Page[PortfolioItemRead]`. Пустая витрина: `items: []`, `total: 0`,
`pages: 0`. Страница за диапазоном тоже `200` с пустым `items`.

Элемент:

```json
{
  "id": 12,
  "title": "Квартира на Садовой",
  "slug": "kvartira-na-sadovoy",
  "description": "Планировка и визуализация.",
  "cover_image": "https://example.com/cover.jpg",
  "is_published": true,
  "sort_order": 0,
  "created_at": "2026-08-16T10:12:00+00:00",
  "category": { "id": 1, "name": "Квартира", "slug": "kvartira" },
  "tags": [{ "id": 2, "name": "Визуализация", "slug": "vizualizaciya" }],
  "images": [
    { "id": 8, "url": "https://example.com/1.jpg", "alt": "Гостиная", "sort_order": 0 }
  ]
}
```

`cover_image` и `images[].url` — строки-URL. Их можно вставить вручную или
получить, загрузив файл через `POST /api/v1/admin/media/upload` (см. ниже).

Ошибки: `422` при `page < 1` или `size > 100`.

### `GET /api/v1/portfolio/{slug}`

Опубликованная работа. Черновик для гостя неотличим от отсутствия: `404`.

## Админ

Заголовок: `Authorization: Bearer <JWT>`. Без токена или с неверным — `401`
(`WWW-Authenticate: Bearer`).

### `POST /api/v1/admin/login`

Тело: `{ "username", "password" }`. Неверный логин и неверный пароль дают
одно и то же сообщение: «Неверные учётные данные».

Ответ `200`: `{ "access_token", "token_type": "bearer" }`.

### `GET /api/v1/admin/me`

Текущий администратор: `{ "username" }`.

### `POST /api/v1/admin/logout`

Клиент отбрасывает токен. Сервер сессий не хранит.

### Портфолио

Префикс `/admin`, чтобы не пересечься с публичным `GET /portfolio/{slug}`.

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/api/v1/admin/portfolio` | Все работы, включая черновики (пагинация как у витрины) |
| `POST` | `/api/v1/admin/portfolio` | Создать |
| `GET` | `/api/v1/admin/portfolio/{id}` | Одна работа по id |
| `PATCH` | `/api/v1/admin/portfolio/{id}` | Частичная правка |
| `DELETE` | `/api/v1/admin/portfolio/{id}` | Удалить, `204` |

Тело создания (`PortfolioItemCreate`):

| Поле | Тип | Обязательное | Ограничения |
| --- | --- | --- | --- |
| `title` | string | да | 1–200 символов |
| `slug` | string | да | 1–220, kebab-case `^[a-z0-9]+(?:-[a-z0-9]+)*$`, уникален |
| `description` | string | нет | до 10 000, по умолчанию `""` |
| `cover_image` | string \| null | нет | до 500, URL |
| `is_published` | bool | нет | по умолчанию `true` |
| `sort_order` | int | нет | по умолчанию `0` |
| `category_id` | int \| null | нет | |
| `tag_ids` | int[] | нет | |
| `images` | `{url, alt?, sort_order?}[]` | нет | URL кадров галереи |

Если `cover_image` пустой, а галерея не пустая — обложка берётся из кадра
с минимальным `sort_order`.

`PATCH` — те же поля, все опциональны (`PortfolioItemUpdate`).

Ошибки: `401`, `404`, `409` (slug занят), `422`.

### Загрузка изображений

`POST /api/v1/admin/media/upload` — multipart-загрузка одного файла (поле
`file`). Требует авторизации. Принимает JPEG/PNG/WEBP/GIF, максимум 8 МБ.
Файл сохраняется в `MEDIA_ROOT` под случайным именем и раздаётся статикой
по `MEDIA_URL_PREFIX` (`/media` по умолчанию).

Ответ `201`:

```json
{ "url": "/media/1a2b3c4d5e6f.jpg" }
```

Полученный `url` передаётся как `cover_image` или элемент `images[].url` в
`POST`/`PATCH /admin/portfolio`.

Ошибки: `401` без токена; `422` при неподдерживаемом типе, пустом или
слишком большом файле.

### Категории и теги

| Метод | Путь |
| --- | --- |
| `POST` | `/api/v1/admin/categories` |
| `DELETE` | `/api/v1/admin/categories/{id}` |
| `POST` | `/api/v1/admin/tags` |
| `DELETE` | `/api/v1/admin/tags/{id}` |

Тело создания: `{ "name", "slug" }`. Нельзя удалить категорию, пока к ней
привязаны работы (`409`).

## Заявки

### `POST /api/v1/leads`

Форма-заявка на проект интерьера с сайта-визитки.

Тело запроса:

| Поле | Тип | Обязательное | Ограничения |
| --- | --- | --- | --- |
| `name` | string | **да** | 2–120 символов, лишние пробелы схлопываются |
| `phone` | string | **да** | 7–25 символов ввода, 10–15 цифр после нормализации |
| `email` | string \| null | нет | валидный email, до 254 символов |
| `message` | string \| null | нет | до 2000 символов |

**Нормализация телефона.** Номер приводится к виду `+<цифры>`: удаляются
пробелы, дефисы и скобки, а российский формат `8XXXXXXXXXX` превращается в
`+7XXXXXXXXXX`. То есть `8 (999) 123-45-67`, `+7 999 123 45 67` и `+79991234567`
сохранятся как одна и та же строка `+79991234567`. Это же значение
используется для проверки дубликатов.

Запрос:

```json
{
  "name": "Анна Петрова",
  "phone": "8 (999) 123-45-67",
  "email": "anna@example.com",
  "message": "Квартира 72 м², нужен проект и визуализация"
}
```

Ответ `201`:

```json
{
  "id": 1,
  "name": "Анна Петрова",
  "phone": "+79991234567",
  "email": "anna@example.com",
  "message": "Квартира 72 м², нужен проект и визуализация",
  "status": "new",
  "created_at": "2026-08-16T11:30:00+00:00"
}
```

Значения `status`: `new`, `in_progress`, `done`, `rejected`. Новая заявка
всегда создаётся со статусом `new`.

Ошибки:

- `409` — с этого номера уже приходила заявка за последние 5 минут
  (антидубль от повторного нажатия кнопки, константа `DUPLICATE_WINDOW`
  в `app/services/lead_service.py`).
- `422` — телефон отсутствует или не проходит валидацию, некорректный email,
  слишком короткое имя.

Если заданы `SMTP_*` и/или `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`,
после сохранения заявки уходит уведомление. Ошибка канала заявку не откатывает.

## Транзакции

Один HTTP-запрос — одна транзакция. Сессия отдаётся зависимостью `get_db`,
коммит происходит при успешном завершении запроса, откат — при любом
исключении. Репозитории делают только `flush`, чтобы получить `id`, и не
управляют границами транзакции.
