# AGENTS.md

Этот репозиторий содержит фронтенд на React и бэкенд на FastAPI.


## О проекте
- Бренд: **Плюс Дизайн**. Сайт-визитка дизайнера интерьера Анастасии Плюсниной.
- Услуги: проектирование и визуализация интерьеров квартир и домов, авторский надзор. Опыт — 4 года.
- Japandi — только стиль UI, не тема интерьеров и не описание услуг. См. `docs/fronted.md`.
- Фронтенд: React + TypeScript. Задача: портфолио + форма заявки.
- Бэкенд: FastAPI + Python.
- Подробности: `README.md` и `docs/`

## Структура репозитория
- `frontend/` — React-приложение
- `backend/` — FastAPI-приложение
- `docs/` — архитектура, решения, заметки
- `tests/` — интеграционные или e2e-тесты, если они есть

## Общие правила работы
- Вноси минимальные изменения, достаточные для задачи.
- Не трогай чужой код без необходимости.
- Следуй существующим паттернам в ближайших файлах.
- Если изменение затрагивает фронтенд и бэкенд, обновляй обе части согласованно.
- Если задача затрагивает БД, авторизацию или деплой, сначала проверь контекст в документации.

## Правила для фронтенда
- Компоненты должны быть небольшими и переиспользуемыми.
- Используй TypeScript для типов пропсов, ответов API и состояния.
- Переиспользуй существующие UI-компоненты и стиль проекта.
- Если меняется контракт API, обнови типы и использование данных на фронтенде.

## Правила для бэкенда
- Делай обработчики маршрутов тонкими, бизнес-логику выноси в отдельные сервисы, если это уместно.
- Использую паттерн DDD (Domain-Driven Design) для организации кода.
- Все зависимости должны быть направлены во внутрь, а не наружу (например, сервисы не должны напрямую зависеть от FastAPI).
- Используй асинхронные функции для работы с I/O (например, с базой данных или внешними API).
- Пиши тесты для новых функций и изменений в существующих.
- Используй Pydantic-модели для валидации входных и выходных данных.
- Не ломай текущий API без явной необходимости.
- Если меняется поведение эндпоинта, добавь или обнови тесты.

## Команды
### Фронтенд
- Установить зависимости: `cd frontend && npm install`
- Запуск в разработке: `cd frontend && npm run dev`
- Сборка: `cd frontend && npm run build`
- Тесты: `cd frontend && npm test`

### Бэкенд
- Установить зависимости: `cd backend && pip install -r requirements.txt`
- Запуск в разработке: `cd backend && uvicorn app.main:app --reload`
- Тесты: `cd backend && pytest`
- Линт: `cd backend && ruff check .`

## Проверка изменений
- Перед завершением проверь релевантные тесты.
- Убедись, что приложение запускается после изменений.
- Проверь форматирование и линт, если код менялся.
- Сверь итоговый diff, чтобы там были только нужные изменения.

## Подсказки для агента
- Если контекста не хватает, сначала смотри `README.md` и `docs/`.
- Если поведение неясно, ищи тесты или существующие примеры.
- Старайся делать маленькие, понятные изменения.
- Сохраняй существующие имена, обработку ошибок и формат ответов API.
